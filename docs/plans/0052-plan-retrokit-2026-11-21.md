# Plan: retrokit, a retrospective on an agent session

## Context

No kit in the collection takes a finished session as its input. reviewkit reads a diff, refactorkit reads the code, handoffkit carries a session forward, and skillkit re-checks one skill you already suspect. When a session goes badly (a long search, a mistake a lint rule could have caught, a kit that asked when it should have decided), nothing asks why the environment allowed it, so the same friction repeats in the next session.

Matt Pocock's `retro` skill (mattpocock/skills, `skills/engineering/retro/SKILL.md`, described at aihero.dev/skills-retro) fills this gap for his set. It reads a session transcript, finds the moments of friction in seven categories (navigation, automated checks, coding standards, an oversized `AGENTS.md`, tool economy, no-ops, information access), sends each fix to the cheapest place that prevents a repeat, and ranks the candidates without changing anything. Its documented failures are generic advice that no transcript moment supports, and overweighting whatever one session happened to cover.

retrokit is our version, written from scratch to the collection's conventions. It differs from the original in four ways: every candidate quotes the transcript moment it comes from, our own kits are a first-class target, each candidate routes to the kit that owns the fix, and every report is saved so later retros can see a friction that repeats.

**Goal.** Friction that an agent hits once becomes a change to the environment (a check, a pointer, a kit fix, a deletion) rather than a repeat.

**Target.** Proposed, no baseline because the skill is new. On a backtest of three real sessions, every candidate carries a transcript quote, and on the session where afkkit paused to ask open questions, the top three candidates include the decision-policy fix that commit `4d68fce` later made by hand.

## Design decisions (settled)

| Decision | Resolution |
|----------|-----------|
| New skill or a mode | New skill `retrokit`. "That session went badly, find out why" is a distinct moment a person chooses. It is not a mode of handoffkit (forward-looking state), reviewkit (diff input), or skillkit (one named skill). |
| Visibility and invocation | Public (`internal: false`), `disable-model-invocation: true`. Only the user starts a retro, so no other kit dispatches to it; siblings name it. |
| What retrokit changes | Nothing outside its report. It proposes, ranks, and routes each candidate to the kit that owns the fix: skillkit for a kit defect, implementkit for a check or a code change, domainkit for a glossary gap, wikikit for a stale doc, or a plain-language edit when no kit fits. Same shape as refactorkit and debugkit. |
| Session scope | Default: the current session, or a named session of the current repo and its worktrees. Mode `all`: any session log on the box. |
| Report | Saved every run to `docs/retros/NNNN-retro-<slug>-YYYY-MM-DD.md`, per the collection's artifact naming. A later retro reads the earlier reports, and a friction already reported ranks higher. |
| Evidence gate | Each candidate quotes the transcript moment (a tool call, an error, a user correction) and names its cost (tool calls, turns, or a user correction). A candidate with no quote is dropped. A report with no candidates is a valid result. |
| Mechanical versus judgement | A mechanical violation (a fixed pattern, a banned API, a file-location rule) routes to a deterministic check in the repo's own lint, hook, or CI. Only a judgement call becomes prose, in the reviewer-side standards file. |
| Reviewer-side standards | reviewkit's Pass 1 reads `CODING_STANDARDS.md` when the repo has one. retrokit proposes creating it on the first accepted judgement rule. The implementer's always-loaded `AGENTS.md` or `CLAUDE.md` keeps navigation pointers. |
| Deletions | A no-op instruction or misplaced steering is a full candidate, ranked like an addition. This matches the Pruning rules in `AGENTS.md`. |
| Reading a log | Never read a raw transcript into context. Logs here run from 0.6 to 6 MB. Extract a digest first (user turns, tool calls with their errors, retries, corrections) and read the excerpts the digest points at. |
| Finding this repo's sessions | A session belongs to the repo when its log's `cwd` field is inside the repo root, a live worktree from `git worktree list`, or gitkit's worktree root for this repo, which catches removed worktrees. gitkit owns that path; without gitkit, a removed worktree's session is named by its log path. |
| Host logs | Claude Code (`~/.claude/projects/<slug>/<id>.jsonl`, with `subagents/`) and Codex (`~/.codex/sessions/YYYY/MM/DD/*.jsonl`). Both carry `cwd`. With neither, retro the current session from context and say so in the report. |
| Digest | A subagent reads the raw log, subagent logs included, and returns a digest: user turns, tool errors, retries, user corrections, interruptions, each with its log line. The main context reads only the digest and the excerpts it points at. No fixed `jq` recipe. |
| `all` mode report | Lands in the repo retrokit runs in. Each candidate carries a `Target:` line naming the repo that owns the fix. |
| Committed reports and redaction | Reports are committed. A quote is at most 200 characters, and secrets, tokens, and keys become `<redacted>`. |
| Private session, public report | Before writing, check visibility with `gh repo view --json visibility` for the run repo and the session repo. When the run repo is public and the session repo is private or unknown, the candidate gives a paraphrase and `<log path>:<line>` in place of the quote. |
| Repeat ranking | A candidate already in an earlier `docs/retros/` report moves up one severity level and cites that report's path. |
| Smooth session | Zero candidates is a valid report, with no warning. |
| Directory group | "Skill & Prompt Authoring" in `skills.sh.json`, with its description widened. |
| Test approach | `skills/retrokit/evals/triggers.md` plus the Phase 4 backtest. No new runner. |
| Who starts a retro | Only the user, with `/retrokit`. afkkit never starts one: the agent that struggled would grade its own run, a retro needs a person to drop the candidates that are not real, and a retro after every run adds rules nobody needs. Decided 2026-11-21, after the grill. |
| afkkit run evidence | afkkit's PR body ends with `afkkit run: <host> session <id>` when the host exposes the id, with no local path. Its hand-off gives the session log path. retrokit finds an afkkit run by that id, else by the PR URL or `afkkit <n>` in the logs, and reads the PR body for the open problems and decisions. `.afkkit/` is read only while the worktree exists. |
| Where it sits in the loop | A side kit that starts from a bad session, like debugkit starts from a symptom. It is not a loop step, and statuskit gets no rung for it. |

## Approach

retrokit is one `SKILL.md` with a short `all` branch inside it, not a routing root with mode files, because both modes walk the same steps and differ only in which logs they may open. It reuses:

- The evidence rule and severity scale of reviewkit (`skills/reviewkit/SKILL.md`, Pick the review target and Report the findings).
- The propose-and-crown shape of refactorkit (`skills/refactorkit/SKILL.md`).
- skillkit's Maintain an existing skill procedure as the owner of every kit-defect candidate.
- afkkit's run directory (`.afkkit/assumptions.md`, `problems.md`, `progress.md`) as a second input beside the transcript of an unattended run.
- The collection's Pruning vocabulary (no-op, two loads, prompt the positive) as the definitions behind the deletion categories.

Rejected: a mode in handoffkit (wrong direction, and a different output); an `apply` step that edits the target (it would duplicate implementkit and skillkit).

### Phase 1: Draft retrokit (built 2026-11-21)

- Write `skills/retrokit/SKILL.md` with the frontmatter template, `metadata.internal: false`, `disable-model-invocation: true`, and an `allowed-tools` list without `Edit`.
- Steps, each with a completion criterion: pick the session (the current one by default, a named one, or with `all` any on the box); dispatch the digest subagent; find the friction moments with a quote and a cost each; classify each moment into a category and a target; check earlier reports in `docs/retros/` for a repeat; rank; write the report; hand off with one crowned candidate and its owner kit.
- Categories: Matt's seven, plus **kit defect** (a skill step with a vague completion criterion, a trigger that did not fire, a kit that asked where it should decide).
- Degrade without a log: retro the current session from context, and say so in the report.
- Write the redaction rule and the visibility check into the report step.
- Write `skills/retrokit/evals/triggers.md` with `Should fire` and `Should not fire` lists.

Done when: `make lint` reports no errors for `skills/retrokit/`, and every step in the file ends on a completion criterion.

### Phase 2: Wire the siblings (built 2026-11-21)

- reviewkit, Pass 1: Convention-fit: add `CODING_STANDARDS.md` to the list of stated convention docs.
- afkkit, Open the PR: end the body with the `afkkit run: <host> session <id>` line when the host exposes the id.
- afkkit, Hand off: give the session log path under Where it landed. When the run ended **opened as draft** or **stopped**, or ran a fix round, add one runner-up line that names `/retrokit <session log path>`.
- `docs/wiki/workflow.md`: add retrokit to The side kits, and name the afkkit route in Unattended: afkkit.

Done when: `make lint` passes, and `grep -n retrokit skills/reviewkit/SKILL.md skills/afkkit/SKILL.md docs/wiki/workflow.md` shows the afkkit line and the workflow entry, and `grep -n CODING_STANDARDS skills/reviewkit/SKILL.md` shows the Pass 1 line.

### Phase 3: Collection surfaces (built 2026-11-21)

- `skills.sh.json`: add retrokit to the "Skill & Prompt Authoring" group and widen the group description to cover tuning the agent's environment from a session.
- `docs/wiki/index.md`: link retrokit under the same theme group.
- Run `make cheatsheet` and commit the regenerated page.

Done when: `make lint` reports no errors, including the index-versus-`skills.sh.json` check and the cheatsheet diff.

### Phase 4: Backtest on real sessions

Attended: the user picks the three sessions and judges whether each candidate is real.

- Run `make link` for retrokit, then run it on three sessions: the afkkit session that paused to ask open questions, one smooth session, and one session from another repo through `all`. Look for the pause session first in the Codex afkkit logs under `~/.codex/sessions/2026/11/16/`.
- Check that the `all` report on a private-repo session uses paraphrases and log pointers, not quotes.
- Fix the skill for each miss through skillkit's Maintain an existing skill procedure.

Done when: each of the three reports is saved under `docs/retros/`, every candidate in them carries a transcript quote or, for a private session, a log pointer, the smooth session yields zero or one candidate, and the afkkit-pause report ranks the decision-policy fix in its top three.

## Open questions

None. The grill on 2026-11-21 settled every point.

## Non-goals

- No automatic or scheduled retros, and no statuskit rung.
- No edits to the target: retrokit never writes a check, a standards line, or a skill change itself.
- No memory system. retrokit does not write agent memory files; a fix belongs in the repo.
- No metrics dashboard across retros beyond reading earlier reports for repeats.
- No audit of old checks or rules that no session exercised.
