# Plan — uikit

Grilled: 2026-08-06

_Created 2026-08-06._

## Context

The collection can take an idea from validation to a merged PR, and at no point does anything in it know what good looks like on screen. `implementkit` writes whatever code satisfies the issue. `reviewkit` checks conventions, agent slop, completeness, and correctness — all by reading source, none of it visual. `verifykit` photographs the result for a PR but passes no judgment on it. `designkit` records the design system and is emphatic that it is **not a UI generator**. So a frontend feature built through this loop gets shipped, reviewed, proven, and documented without one step asking whether it looks like every other thing an LLM has ever produced.

It usually does. AI-generated UI has a recognizable signature — the three equal feature cards, the purple gradient, Inter on slate-900, the div-built fake dashboard in the hero, the `01 / 02 / 03` eyebrows over content that isn't a sequence. These aren't bugs and no test catches them. They're defaults, reached for because the model had no reason to reach anywhere else.

**uikit is the reason.** It generates production UI that reads as a deliberate choice for *this* project, and it audits shipped UI for the tells when the horse has already left. It is the consumer side of the contract `designkit` writes: designkit derives `DESIGN.md` from the UI a project already ships, uikit reads that file and builds the next screen inside it. Between them the design system stops being documentation nobody applies.

**Success:** point uikit at a UI task in a repo with a `DESIGN.md` and get components that a reader would guess a designer specified — conforming to the recorded system, distinctive where the system leaves room, accessible without being asked, and free of the signature tells. Then point `uikit audit` at UI built before the skill existed and get a ranked, `file:line` list of what gives it away.

## Design decisions (settled)

Settled with the user on 2026-08-06 across the plankit scoping pass and a two-round grill.

| Decision | Resolution |
|----------|-----------|
| **Name** | `uikit` — kept, per the backlog entry. The collision with Apple's UIKit is real and accepted deliberately: the `kit` suffix is the brand across all 24 skills, "ui" leads so search works, and nobody installing an agent skill is looking for an Objective-C framework. Rejected `frontendkit` (vaguer, and the work is specifically visual), `designkit` (taken, different job), `slopkit` (names the enemy, not the job). |
| **Modes** | **Two: `build` / `audit`.** `build` generates UI. `audit` sweeps existing UI against the anti-slop catalog and **writes nothing, ever**, mirroring `designkit audit` and `wikikit audit`. The audit half is a genuine gap — `reviewkit`'s agent-slop pass hunts code signatures (dead abstractions, over-commenting, defensive noise), not visual ones. Rejected build-only (the tells that matter most are already shipped in every project that predates the skill) and a third `direct` mode (the design read is a few declared words inside `build`; a standalone artifact for it is ceremony). |
| **The precedence ladder** | The spine of the skill, and what makes a *generative* skill fit a collection built on grounding. Taste is spent only where nothing else constrains the choice: **1. `DESIGN.md`** when it exists — its tokens are the palette, full stop. **2. The shipped components** — an existing Button is the Button; uikit conforms rather than expressing itself. **3. The subject's own world** — Anthropic's strongest idea, that distinctive choices come from the product's materials, vocabulary, and artifacts, not from a style catalog. **4. uikit's stack defaults**, last. A project with a design system gets consistency; a greenfield one gets a point of view. Neither gets a default reached for by reflex. |
| **Surface scope** | **Both product UI and marketing/landing, one catalog, every tell scope-tagged** `product` / `marketing` / `both`. The two surfaces have disjoint slop signatures — the agency-portfolio tells (rotated vertical text, locale/weather strips, `Scroll ↓` cues) don't fire on a settings page, and the product tells (missing empty states, unlabeled icon buttons, tables with no zero-row case) don't fire on a hero. The design read declares the surface and the pre-flight runs only the entries that fire. Rejected product-only (forfeits the most recognizable slop of all, and the backlog says "stunning production UI/UX") and splitting the catalog or the modes (doubles the surface for a distinction one declared word already carries). |
| **The signature** | **Distinctiveness ships as *the signature*, not as "take a risk."** One named element per surface — the thing the page is remembered by — declared in the design read and constrained by the rung: at **rungs 1–2** the licensed materials are composition, interaction, and motion; at **rungs 3–4** they extend to palette, type, and grid. This is a deliberate reframe of Anthropic's "take one real aesthetic risk," which is motivationally right and operationally unusable: a model asked for boldness retrieves *what boldness looks like*, and what it retrieves is the average — the cream/serif/terracotta cluster that skill itself names as a current AI default. Specificity has no average to regress toward. It's also the only version that survives the pre-flight, which can check *exactly one signature exists* and *its materials are legal at the declared rung* but cannot check whether a risk was taken. Rejected always-fire (a rogue component in every established codebase) and dropping it (uikit becomes a conformity checker, and boring UI is a different failure from sloppy UI, not a fix for it). |
| **The design read** | **Five declared words, no numeric scales:** surface, audience, rung, signature, density (`compact` / `comfortable` / `spacious`). The reference implementations expose three 1–10 dials; two of them are already covered — variance *is* the rung, motion *is* the motion-discipline rule — and density is the one axis that genuinely varies independently of the rung, so it ships as a word. A 1–10 scale is false precision: nobody can defend why 7 differs from 6, and the model can't either. |
| **Stack policy** | **Detect first, house default second.** Read the project's real stack and follow it. When greenfield or undeclared, default to **Tailwind v4 + shadcn/ui** and say so out loud in the design read. The stack-specific rules ship as a named section a non-Tailwind project skips whole: shadcn composition (`FieldGroup`/`Field` for forms, `gap-*` never `space-y-*`, semantic tokens never raw `bg-blue-500`, no manual `dark:` overrides, `asChild`/`render` for triggers, `size-*` over `w-N h-N`) and Tailwind v4 correctness (CSS-first `@theme`, the v3→v4 renames that silently render *smaller* rather than erroring — `shadow-sm`, `rounded-sm`, `blur-sm`, `outline-none`, `ring`, `bg-gradient-to-r`). Rejected stack-agnostic (throws away the rules that catch half of real UI slop) and Tailwind-only (wrong for a public skill). |
| **Boundary — implementkit** | **uikit writes and audits UI code; `implementkit` delegates to it for UI work and keeps every gate.** implementkit retains the input contract, mode resolution, and the repo-discovered done-gate; it gains exactly one line in its build step — *if the work includes a visual surface and uikit is installed, apply it to those files* — and nothing else moves. **uikit's pre-flight is a self-critique, never a pass/fail gate**, because a build that can fail for taste reasons fails on a check that is unfalsifiable and unbounded. Run standalone, uikit runs its pre-flight and runs the repo's gate only if one exists. Rejected uikit owning a second gate (afkkit trusts implementkit's gate and would now face two) and no pointer at all (leaves the default path exactly as broken as today). |
| **Boundary — designkit** | **uikit reads `DESIGN.md`, never writes it.** One owner per artifact, and designkit's grounding rule (every token must appear in the codebase) cannot survive a skill that both invents the taste and records it. When no `DESIGN.md` exists, uikit establishes a direction inline for the build and routes to `designkit init` afterward to record what it just shipped — which is exactly designkit's derive-from-shipped-UI job, now with something to derive from. |
| **`audit` targeting** | **Explicitly named paths → UI files in the working tree or branch diff → ask.** Paths lead because the UI most worth auditing predates the skill and appears in no diff at all; "audit our UI" is the actual ask, and a diff cannot answer it. The seam with `reviewkit` holds without either skill deferring: reviewkit's agent-slop pass reads *code* signatures, uikit's reads *visual* ones, so running both on one diff produces complementary findings rather than duplicates. The mandatory coverage line stays, so an audit that reached three files can't read as a clean bill of health. Rejected diff-only (consistent with reviewkit and unable to answer the real question) and whole-repo sweeps (unbounded on any real app). |
| **Self-critique** | **Written pre-flight is the default and always runs; pixels are opt-in.** The pre-flight is a curated pass over the anti-slop catalog, the accessibility floor, and the two signature checks, and it's the mode that actually fires in headless CI and locked-down VMs. Screenshot critique is an explicit ask ("look at it") that uses only what's already present — a browser-automation MCP, an installed Chromium, an existing Playwright. **uikit never installs a browser and never starts a dev server it wasn't told to start.** No backend means one honest line naming the gap, and the checklist result stands on its own rather than being framed as a failure. |
| **Catalog discipline** | **Bar, cap, and a displacement rule — the mechanism the intent was missing.** A tell earns a line only if it is stateable as a **ban with the correct alternative beside it** *and* an agent can **check its own output for it without rendering**. The cap is **~30 entries, enforced by displacement**: entry 31 means deleting one of the 30, so the list can only improve rather than grow. The reference implementations run to ~100 pre-flight checkboxes; nobody honestly ticks 100 boxes, so a list that long is decoration, and "soft target" is what every one of them called itself at item 40. Vercel's `file:line` output format is the model for `audit` — terse, clickable, no preamble. |
| **UI copy** | uikit writes the strings on screen, following `DESIGN.md`'s Do's and Don'ts voice rules when the file has them (designkit already puts voice there deliberately). The em-dash ban and the "Jane Doe / Acme / 99.99%" placeholder-data tells apply to **interface strings**, not to repo prose — `humankit` owns prose and gets offered as a follow-on pass. |
| **Accessibility floor** | **Inlined, not fetched.** A non-negotiable baseline every build clears without announcing it: visible `:focus-visible`, `prefers-reduced-motion` honored, WCAG AA contrast, semantic elements before ARIA, labeled controls, `alt` on images, keyboard reachability. Rejected fetching Vercel's guidelines live (a portable skill can't depend on network egress) and treating a11y as an audit-only concern (it's a floor, not a finding). |
| **Unattended runs** | **In `afkkit`'s span implicitly, under a no-ask contract.** uikit is already in the span transitively — afkkit dispatches implementkit, which now delegates UI — so the live question is what makes it *safe* there. Answer: **uikit never blocks on a design question.** The design read is a declaration, not an interview; at rungs 3–4 it infers the subject from repo context and states the inference. Wrong-but-stated beats correct-but-hung, and a stated read is what a reviewer corrects. Rejected an explicit afkkit step (afkkit adds no logic of its own and sequences companion kits) and suppressing uikit unattended (that's precisely where blind defaults ship, since no human sees the UI before the PR). |
| **Durable artifact** | **None beyond the hand-off.** The design read is a **required line in uikit's `## Hand off`**, which carries it through implementkit → afkkit → prkit into the PR body — where a reviewer actually reads it — without inventing a file. Routing to `designkit init`/`update` afterward is the durable answer. Rejected a per-build note under `docs/design/` (a second design-system-ish artifact competing with `DESIGN.md`) and appending to `DESIGN.md` (violates the never-writes-it decision). |
| **Visibility** | **Public** (`internal: false`). Conventions inlined, no repo-relative links, no dependency on `make`/`AGENTS.md`/`scripts/`. Degrades to printing components as fenced blocks when there's no writable filesystem. |
| **Layout** | **Single flat `skills/uikit/SKILL.md`** — confirmed, not assumed. The catalog cap is what settles it: ~30 scope-tagged entries fit one file comfortably, and the displacement rule keeps them there. Consistent with all 23 existing skills; `verifykit`'s `verify-assets.sh` is the collection's only second file, and it's a script rather than prose. A `skills/uikit/references/` split would make room the content doesn't need. |

## Approach

**Reuses, rather than reinvents:** `designkit`'s `DESIGN.md` schema and its "audit writes nothing, ever" mode contract; `reviewkit`'s severity ranking (🔴 Blocker / 🟡 Should-fix / 🟢 Nit), its mechanical verdict, and its working-tree-then-branch-diff target resolution via `gitkit`; `verifykit`'s capability-ladder-then-degrade-honestly pattern for browser backends; `implementkit`'s done-gate discovery from the repo's own manifests; `wikikit`'s "a claim it cannot ground does not ship" rule; the `Hand off` three-beat closing and the `plan-<slug>-YYYY-MM-DD.md` artifact convention already in force.

### Phase 1 — Frontmatter, triggers, and the boundary paragraph

Write the `name`/`description`/`license`/`metadata.internal: false` block with a front-loaded "Use when…" trigger covering both modes and the plain-English asks ("build this page", "this looks AI-generated", "make the UI not look like slop", "audit our UI"). The opening section names the four things uikit is **not** — not the design-system recorder, not the PR proof producer, not the code reviewer, not a palette-and-font-pairing catalog — because three of those are sibling skills and the fourth is the shape most competing skills take.

### Phase 2 — The precedence ladder

The section every other section defers to. Four rungs, first match wins, and **uikit states which rung it landed on before writing any code**. Includes the detection method per rung (`DESIGN.md` at repo root, component directory + `components.json`, the product's own domain vocabulary from `CONTEXT.md`/README/routes), the rule that a lower rung never overrides a higher one, and the **signature materials each rung licenses** — composition, interaction, and motion at rungs 1–2; palette, type, and grid added at rungs 3–4.

### Phase 3 — The design read

Five declared words before generation: **surface** (product or marketing), **audience**, **rung**, **signature** (the one element the surface is remembered by, and the material it's made from), **density**. Cheap, and it's what stops the model jumping straight to a default aesthetic. Carries the **no-ask contract** — the read is stated, never asked, so uikit is safe unattended. Includes the anti-default discipline: the named list of what AI UI converges on, stated so it can be deliberately avoided rather than accidentally reproduced, including the three clusters a model reaches for when it's told to be bold.

### Phase 4 — Mode: `build`

Ground → design read → build → pre-flight → hand off. Covers the stack detection and its house default, the composition-over-invention rule (use the existing component before writing a styled `div`), the accessibility floor, motion discipline (justifiable in one sentence, `transform`/`opacity` only, never `transition: all`), and the gate boundary — **implementkit's done-gate is the only gate**; uikit's pre-flight is a self-critique that never fails a build. Standalone, uikit runs the repo's gate only if one exists. The hand-off carries the design read verbatim so it survives into a PR body.

### Phase 5 — Mode: `audit`

Read-only. Target resolution in order — **named paths → UI files in the working tree or branch diff → ask** — then the scope-filtered catalog sweep, `file:line` findings ranked by severity, a mechanical verdict, and a mandatory coverage line so an audit that reached three files can't read as a clean bill of health. Routes findings back to `build` rather than fixing them itself. States the reviewkit seam explicitly so neither skill defers to the other by accident.

### Phase 6 — The anti-slop catalog

The curated tell list, grouped by where it bites: visual and CSS, typography, layout, placeholder content and copy, fake-product-preview patterns, and the product-UI state gaps (missing empty, loading, error, and zero-row states). Every entry carries a **scope tag** (`product` / `marketing` / `both`), a **ban**, and the **correct alternative**. The bar and the ~30 cap with its displacement rule are written into the section itself, so the discipline travels with the catalog rather than living only in this plan.

### Phase 7 — The stack layer

The Tailwind v4 + shadcn section, skippable whole by a project on another stack. Correctness rules that prevent silent wrongness, not style preferences.

### Phase 8 — Self-critique and degradation

The written pre-flight — scope-filtered catalog, accessibility floor, and the two signature checks (**exactly one exists**, **its materials are legal at the declared rung**) — then the opt-in pixel path and its backend ladder, and the degrade-loudly rule. Explicitly: never install a browser, never start a dev server unbidden, never claim a visual check that didn't happen.

### Phase 9 — Integration

`implementkit` gains **one line** in its build step delegating visual surfaces to uikit when installed, and keeps every gate. `designkit` gains nothing (its "not a UI generator" line already anticipates this skill and now has something to name). `afkkit` gains nothing — uikit rides in through implementkit. `WORKFLOW.md` gains uikit in the BUILD phase. `README.md` skills table, `skills.sh.json` (the **Building** group, alongside `implementkit`), and the `uikit` row deleted from `IDEAS.md` per its own graduation rule.

### Phase 10 — Test live

`make link`, run both modes against a real frontend, confirm `make lint` passes.

## Open questions

**None.** All eight questions this plan opened were settled in the 2026-08-06 grill; nothing was deferred. The load-bearing changes were the reframe of "take one real aesthetic risk" into **the signature** (checkable, and immune to the boldness-retrieves-the-average failure), the **displacement rule** that gives catalog discipline an actual mechanism, and the **no-ask contract** that makes uikit safe unattended. Two decisions the plan had listed as settled were confirmed rather than assumed — single-file layout now follows from the catalog cap, and the implementkit boundary now names the gate owner explicitly.

## Non-goals

- **Not the design-system recorder.** `DESIGN.md` has exactly one owner and it is `designkit`. uikit reads it and routes back to designkit when it needs writing.
- **Not a taste library.** No bundled palettes, font pairings, or style catalog. The competing skills ship 161 palettes and 57 font pairings; that's a lookup table, and a lookup table is how every project styled by it ends up looking like every other one.
- **Not the PR proof producer.** `verifykit` owns screenshots-as-artifacts. uikit's pixels, when it takes any, are a critique input it looks at and discards.
- **Not the code reviewer.** `reviewkit` owns convention-fit, agent slop in code, completeness, and correctness. uikit's audit is visual and interaction-level only.
- **Not a prose humanizer.** `humankit` owns prose. uikit governs strings in the interface, and hands off.
- **Not an environment provisioner.** It never installs a browser, never starts a dev server it wasn't told to start, never seeds data.
- **Not a gate.** The pre-flight critiques; it never fails a build. `implementkit`'s done-gate is the only gate in the delegated path.
- **Does not commit.** `commitkit` does.
- **Not backend, data, or state architecture.** It builds the visual surface, not the system behind it.
