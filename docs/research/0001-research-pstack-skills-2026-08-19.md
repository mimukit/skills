# Research: pstack skills, ranked for the kit workflow

Source: [cursor/plugins → pstack/skills](https://github.com/cursor/plugins/tree/main/pstack/skills), all 44 `SKILL.md` files read in full on 2026-08-19.

pstack is Cursor's in-house agent skill stack. It has three layers: 23 operational skills (workflows like `arena`, `why`, `blast-radius`), 21 `principle-*` leaf skills (short, composable rules other skills cite by name), and one personal mode skill (`poteto-mode`) that routes between them. It is Cursor-native throughout: multi-model `Task` fan-out with GPT/Grok/Claude slugs, `~/.cursor` paths, MCP evidence categories, cloud workers. Anything adopted here needs translation to Claude Code (Agent/Workflow tools, `~/.claude` transcripts, single model family), which the rankings below price in.

Three things stand out before the tables:

1. **The evidence posture is the best part.** `blast-radius`'s five-rung confidence ladder ("you said so" → "you ran it"), `why`'s null-results-are-findings coverage map, and `show-me-your-work`'s audit-the-log-against-the-transcript step are all mechanisms that stop an agent from shipping a plausible-sounding writeup as fact. That posture is portable regardless of harness.
2. **The principle-leaf architecture is worth stealing selectively.** Skills citing tiny shared principle skills by name keeps each workflow skill short. Your repo already does the equivalent through `AGENTS.md` conventions and `gitkit`-style shared layers, so the win here is mining individual principles into kit rubrics, not replicating the architecture.
3. **Model diversity is their adversarial engine and your main translation loss.** `arena`, `interrogate`, and `how` critique mode get their signal from cross-family disagreement (Claude vs GPT vs Grok). On Claude Code you approximate it with independent parallel agents and adversarial prompts, which works but is measurably weaker. Rankings discount skills whose entire value is the multi-model panel.

## New skill suggestions

Ranked by how much workflow value each adds. Names follow the kit convention (functional word first, one word, collision-checked).

| Priority | Proposed kit | Modeled on | What it does | Why it earns a slot |
|----------|--------------|------------|--------------|---------------------|
| 1 | `reflectkit` | `reflect`, parts of `automate-me` | After a session (or over recent transcripts under `~/.claude/projects/`), mine for durable learnings, then route each to a concrete edit on an existing kit skill, a lint rule, or a backlog note, with user approval before any edit lands | This repo's whole premise is encoded workflow, yet skill improvement is manual. A retrospective loop that ends in skill diffs (not notes) closes it, and the structural-enforcement check (prefer a `make lint` rule over prose) matches the repo's existing philosophy exactly. Internal-first candidate: start as `internal: true` for this repo, generalize later |
| 2 | `whykit` | `why` | Answer "why is this code shaped this way" from evidence: git/`gh` archaeology always, plus issues, docs, and any connected sources; cited claims, calibrated hedging, null results reported as findings | Fills a real gap: debugkit answers "what broke", researchkit answers "what should we choose", nothing answers "why is this here". Grounds plankit and refactorkit proposals in recorded rationale instead of guesses. The seven MCP categories collapse to git+gh+issues here, which still covers most of the value |
| 3 | `impactkit` | `blast-radius` | Pre-merge impact analysis: state the one fact the change is safe because of, walk the evidence ladder, and prove the fact with a script that runs the real code; hand back proven/unproven honestly | reviewkit judges the diff's quality; nothing hunts breakage *outside* the diff (wire formats, teardown ordering, downstream consumers) or proves safety by execution. Natural mergekit companion during PR review |
| 4 | `explainkit` | `how` | One-shot "how does X work" subsystem walkthrough: Explore-agent fan-out for complex questions, onboarding-level output (overview, key concepts, flow, where things live, gotchas) | wikikit produces durable docs and tutorkit runs multi-session curricula; the everyday "explain this subsystem before I touch it" ask has no home. Cheap to build since Claude Code's Explore agents map directly onto pstack's explorers |
| 5 | `trailkit` | `show-me-your-work` | Shared decision-trail layer: one append-only TSV (what, why, evidence pointer, result) per long run, an end-of-run audit of the log against the transcript, fresh-eyes review of the trail | Follows the gitkit precedent of a shared layer other kits reference. afkkit is the first consumer; any unattended or multi-phase run benefits. Could alternatively land inside afkkit, but a shared layer keeps it reusable from implementkit and mergekit |
| 6 | `arenakit` | `arena` | Fan out N independent attempts at one artifact via the Workflow tool, cross-judge against a rubric, pick a base, graft the losers' best ideas, record rejections | The graft-and-record step is the novel part; judge panels alone are already a Workflow pattern. Decide deliberately between this and extending prototypekit: arena covers any artifact (design docs, configs, prose), prototypekit covers questions answered by throwaway code. If both feel thin, extend prototypekit instead |

Name checks: `whykit`, `explainkit`, `impactkit`, `trailkit`, `arenakit`, `reflectkit` have no well-known tool collisions I'm aware of, but verify against skills.sh and npm before committing (per the naming rule).

| 10 | `refactorkit` | Fold the concrete rubrics into candidate ranking: layers-to-trace and state-to-hold with the 30-second test; the if/else-grew-by-one-branch and second-synced-boolean tells; the temporal-decomposition (phase-named modules) tell | `principle-minimize-reader-load`, `principle-model-the-domain` | refactorkit ranks structural candidates; these tells are grep-adjacent, falsifiable signals that make the ranking defensible instead of taste-based |

## What not to take

- **The multi-model panels as-is.** `setup-pstack`'s per-role model config, `swarm`'s cloud workers, and the GPT/Grok reviewer rosters don't exist in this harness. Approximate with independent parallel agents where the pattern matters (reviewkit, arenakit) and skip the rest.
- **A full principles library.** 21 leaf skills is the pstack team's answer to the problem `AGENTS.md` already solves here. Importing the architecture would duplicate the conventions layer; importing individual principles into kit rubrics (rows 5–12 above) captures the content without the sprawl.
- **`poteto-mode` wholesale.** A personal routing mode is appealing, but CLAUDE.md plus well-written `description` triggers already routes. Revisit only if trigger misses become a measured problem.
