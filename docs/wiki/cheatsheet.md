# Cheatsheet

Every skill, one line each. This is the recall page, not the explanation. For how the skills compose into one loop, read [the workflow](./workflow.md). For a skill in full, follow its name to its `SKILL.md`.

| Skill | What it does |
|---|---|
| [`afkkit`](../../skills/afkkit/SKILL.md) | Run a groomed `ready` GitHub issue through the whole build span unattended, covering worktree, implement, commit, QA plan, acceptance check, fix, and open PR, so one issue reaches a reviewable PR with no human at the keyboard. |
| [`commitkit`](../../skills/commitkit/SKILL.md) | Commit this session's changes with Conventional Commits messages derived from the actual diff, then push them to origin. |
| [`debugkit`](../../skills/debugkit/SKILL.md) | Chase a symptom to its true cause: reproduce it, shrink it, write falsifiable hypotheses, and prove the cause by toggling the symptom on and off, then hand over a failing reproduction instead of a fix. |
| [`designkit`](../../skills/designkit/SKILL.md) | Derive a project's design system from the UI it already ships and keep it true as the code moves, producing a spec-compliant DESIGN.md at the repo root, validated by the official linter. |
| [`domainkit`](../../skills/domainkit/SKILL.md) | Maintain a project's domain model as a consented record of settled understanding: the CONTEXT.md overview and glossary of the ubiquitous language, and docs/adr/ decision records. |
| [`gitkit`](../../skills/gitkit/SKILL.md) | The shared git layer other skills borrow: the worktree path, name, and lifecycle, the base branch, rebase versus merge, branch sync, merged-branch cleanup, lost-work recovery, and stacked branches. |
| [`grillkit`](../../skills/grillkit/SKILL.md) | Grill the user relentlessly about any idea, plan, or design, a round of unblocked decisions at a time, each with a recommended answer, until you both share the same picture. |
| [`handoffkit`](../../skills/handoffkit/SKILL.md) | Compact the current conversation into a handoff document another agent or session can pick up cold: goal, state, next steps, key artifacts by reference, and constraints. |
| [`humankit`](../../skills/humankit/SKILL.md) | Strip the tells of AI-generated writing from prose so it reads like a person wrote it. |
| [`ideakit`](../../skills/ideakit/SKILL.md) | Think an idea through across many sessions, with one ideas repo holding a folder per idea, a jotpad for the thoughts that have none, and one idea open at a time. |
| [`implementkit`](../../skills/implementkit/SKILL.md) | Implement a plan, spec, or issue into working code in straight-through, tests-after, or TDD mode, then run the repo's test and build gate before declaring done. |
| [`issuekit`](../../skills/issuekit/SKILL.md) | Own the GitHub issue lifecycle in five modes: file issues from a plan, start a workable issue in its own worktree, close one once its PR merges, sync PR↔issue links and dependents after merge, and triage the tracker for label and title gaps and for done, duplicate, or obsolete issues. |
| [`mergekit`](../../skills/mergekit/SKILL.md) | Take an open GitHub PR and set it up for review on your machine (worktree, project running, review pack), then merge it once you say so, or service review feedback on a PR you authored. |
| [`motionkit`](../../skills/motionkit/SKILL.md) | Choose the easing, duration, spring, and properties that make web UI motion feel right, then build it, review it in a change or across a codebase, or find why it drops frames. |
| [`namekit`](../../skills/namekit/SKILL.md) | Name a project to a naming convention you already use, then prove the name is free on the domain, npm, and GitHub before you commit to it. |
| [`orcakit`](../../skills/orcakit/SKILL.md) | Keep the Orca desktop app's workspace list honest about the git worktrees your workflow actually creates: link each one to its issue, keep its status current, and clean out the ones whose work already merged. |
| [`paseokit`](../../skills/paseokit/SKILL.md) | Push the git worktrees your workflow actually creates into Paseo's workspace registry, because Paseo discovers nothing on its own. |
| [`plankit`](../../skills/plankit/SKILL.md) | Turn a rough feature or change into a structured plan document (docs/plans/NNNN-plan-<slug>-YYYY-MM-DD.md) before any code: brainstorm the approach, settle the big decisions, and write a plan that can be hardened and turned into issues. |
| [`prkit`](../../skills/prkit/SKILL.md) | Draft and open a GitHub pull request from your branch, with title, summary, and test plan written from the actual commits and diff, then created with the gh CLI, embedding verifykit proof artifacts inline when a bundle is present. |
| [`promptkit`](../../skills/promptkit/SKILL.md) | Sharpen the prompt before you send it, whether the one-shot instruction you're about to hand a coding agent or the system prompt your application ships. |
| [`prototypekit`](../../skills/prototypekit/SKILL.md) | Build throwaway code that answers a question, whether an interactive state model you can drive, a script that measures one thing, or competing UI mocks to choose between, then fold the answer into the decision and delete the code. |
| [`qakit`](../../skills/qakit/SKILL.md) | Generate a QA plan for a feature just implemented, grounded in the actual code changes: the agent runs every check with an observable result, in a headless browser when one is available, and leaves a short manual list of what needs human judgment, saved to docs/qa. |
| [`refactorkit`](../../skills/refactorkit/SKILL.md) | Survey an existing codebase for the structural change worth making, then rank the candidates, crown one, and write it up as a reviewable proposal. |
| [`releasekit`](../../skills/releasekit/SKILL.md) | Cut a release from the Conventional Commits a repo already writes: derive the semver bump and a changelog from the commit range, bump the manifest, tag it, and publish a GitHub release, all behind a mandatory preview. |
| [`repokit`](../../skills/repokit/SKILL.md) | Configure a GitHub repo through gh in four modes: an inferred About description and topics, the workflow labels (issuekit's lifecycle and priority sets plus `ai-review`), a new-repo setup (house settings, baseline files, About, labels), and a docs/ renumbering into creation order. |
| [`researchkit`](../../skills/researchkit/SKILL.md) | Research the credible options for a technical decision and recommend one (a tool, library, framework, architecture, or service) grounded in primary sources with cited, dated evidence. |
| [`reviewkit`](../../skills/reviewkit/SKILL.md) | Review AI-agent-implemented code specifically, in four ordered passes (convention-fit, agent-slop signatures, requirement-completeness, correctness) against the working tree or the branch diff, findings ranked by severity and backed by quoted evidence. |
| [`seokit`](../../skills/seokit/SKILL.md) | Audit a web page, or crawl a whole site, for SEO and AEO gaps (crawlability, on-page, structured data, Core Web Vitals, AI-crawler access, answer extractability), then write a prioritized fix report and a long-term search and AI-visibility plan. |
| [`skillkit`](../../skills/skillkit/SKILL.md) | Create a new AI agent skill from scratch (kit-convention naming, drafting, trigger cases, live testing, publishing), or re-check an existing one after a change. |
| [`statuskit`](../../skills/statuskit/SKILL.md) | Survey a project read-only (working tree, issues and their priority, open PRs, unfiled plans, docs awaiting review) into a one-screen dashboard that crowns one finish-first next move routed to the kit that does it, saved by default as a throwaway snapshot under docs/status/. |
| [`testkit`](../../skills/testkit/SKILL.md) | Retrofit an automated test suite onto a working codebase that has none: rank the untested surface, crown a slice, stand up a runner, and write tests that were each watched to fail before they were kept. |
| [`tutorkit`](../../skills/tutorkit/SKILL.md) | Teach a topic across many sessions, with one learning repo holding a folder per topic, lessons pitched at what you already know, and spaced retrieval that makes it stick. |
| [`uikit`](../../skills/uikit/SKILL.md) | Build production UI that reads as a deliberate choice for this project rather than an LLM default, and audit shipped UI for the tells that give it away. |
| [`validatekit`](../../skills/validatekit/SKILL.md) | Validate a SaaS or startup idea before you build it, with a few forcing questions, an optional market and competitor scan, an honest verdict graded on the evidence you can actually produce, the narrowest wedge worth testing, and one real-world assignment. |
| [`verifykit`](../../skills/verifykit/SKILL.md) | Show a frontend change in a real browser, or prove it for a PR: drive the feature, capture screenshots (plus a short GIF for proof), and publish proof so a pull request can embed it inline; or set up the browser driver and the publish path on a machine. |
| [`wikikit`](../../skills/wikikit/SKILL.md) | Generate and maintain a project's reader-facing documentation in-repo (getting-started, how-to guides, architecture overview, runbooks), every command verified against the code, in four modes: init, update, audit, and an opt-in publish that mirrors the set to the GitHub wiki. |
